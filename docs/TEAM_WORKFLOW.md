# 2인 개발 워크플로

## 작업 방식

- 한 작업은 한 기능 폴더를 주 소유 범위로 삼고 작은 PR로 제출한다.
- 브랜치는 `feature/<이름>`, `fix/<이름>`, `docs/<이름>` 형식을 사용한다.
- 공통 영역인 `src/shared`, `src/models`, `src/config`를 변경할 때는 PR에
  영향 범위를 적는다.
- PR에는 목적, 주요 변경, 직접 확인 방법, 화면 캡처, 남은 TODO를 한국어로
  작성한다.

## 권장 역할 분담

- 이하늘: 공부 세션, 타이머, 페이지와 책 환산, 업적.
- 박지민: 홈 퀘스트, 캐릭터와 방 상태, 스토리와 매거진.
- 공동 작업: 데이터 모델, 공통 UI, 저장소 및 백엔드 인터페이스, 릴리스
  검증.

두 기능이 같은 모델을 필요로 하면 타입과 인터페이스 PR을 먼저 병합한 뒤
각 기능 PR을 진행한다. 환경변수는 커밋하지 않고 `.env.example`만 갱신한다.

## PR 확인 목록

1. `npm run typecheck`
2. 가능한 플랫폼에서 변경 흐름 직접 실행
3. 로딩, 빈 상태, 오류 상태 확인
4. 성장 수치가 `src/config`에 있는지 확인
5. 관련 문서와 TODO 갱신
